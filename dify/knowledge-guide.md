# 점검 지식 올리기 (Dify)

지식은 **4개 데이터셋**으로 나눠 올립니다. 모두 **샘플(가상) 규칙**이며 사내 실제 규정이 아닙니다.
팀 규칙이 정해지면 같은 형식으로 교체하세요. 형식: 파일 1개 = 점검 항목 1개 (문서 ID, 제목, 점검 유형, 적용 상황, 점검 방법, 예시, 예외).

| 데이터셋(이름 예시) | 올릴 파일 | 워크플로 노드 | 개수 |
|---|---|---|---|
| 공통 점검 기준 | `dify/knowledge/*.txt` | 공통 점검 기준 검색 | 16 |
| 설문조사 서비스 지식 | `dify/knowledge-tasks/survey/*.txt` | 업무 지식 검색 - 설문조사 서비스 | 폴더 내 전체 |
| 민원 서비스 지식 | `dify/knowledge-tasks/complaint/*.txt` | 업무 지식 검색 - 민원 서비스 | 폴더 내 전체 |
| 업무상담 서비스 지식 | `dify/knowledge-tasks/consult/*.txt` | 업무 지식 검색 - 업무상담 서비스 | 폴더 내 전체 |

선택한 업무의 지식과 공통 점검 기준이 함께 LLM 에 전달됩니다 (업무 지식이 먼저).
다른 업무의 지식은 검색되지 않습니다. 실제 업무 지식(업무 규칙, 이전 리뷰 기록)은 해당 업무 데이터셋에만 추가하세요.

## 올리는 순서 (데이터셋마다 반복)
1. Dify → 지식 → 지식 만들기 → 위 표의 폴더에서 `.txt` 파일만 선택 (`.DS_Store` 같은 숨김 파일은 올리지 마세요)
2. 청크 설정: 일반, **세그먼트 식별자 `\n\n`**, 최대 청크 길이 1,024 이상, **청크 중첩 0**
3. 미리보기에서 **파일 수 = 조각 수**인지, "점검 방법"과 "예외"가 같은 조각에 있는지 확인
4. 인덱싱 완료 후 검색 테스트로 항목이 나오는지 확인
5. 워크플로 앱에서 각 검색 노드의 지식 데이터셋을 선택 (공통 노드는 이미 선택돼 있으면 유지)

## 워크플로를 새로 가져올 때
- 업무별 검색 노드 3개는 데이터셋이 비어 있습니다. **세 노드 모두 해당 데이터셋을 선택해야 실행됩니다.**
- 기존 앱 설정(모델, 공통 지식, 리랭커, 앱 이름)을 유지하려면 `python dify/build_workflow.py --keep dify/review-agent.yml` 로 다시 만드세요.
- API 호출 입력: `task`(업무명, 선택형), `diff_text`, `git_status`. 웹 화면이 업무 선택값을 `task` 로 전달합니다.

## 확인 필요 (아직 검증하지 못함)
- Dify 에 실제로 가져와 분기·검색이 동작하는지는 미검증입니다. 특히 **IF/ELSE 분기 → 변수 집계기 → 코드 노드** 연결과 `select` 입력의 API 전달을 처음 실행할 때 확인하세요.
- 폐쇄망 임베딩 모델과 Dify 버전별 DSL 호환(IF/ELSE·변수 집계기 노드 형식)은 인프라 담당 확인이 필요합니다.
- 최대 길이 단위(문자/토큰)는 Dify 화면에서 확인하세요.

## 평가 주의
지식 예시에는 `samples/` 의 심어 둔 오류를 넣지 않았습니다 (테스트가 확인). 샘플 정답이 지식에 들어가면 효과를 부풀려 측정하게 됩니다.
